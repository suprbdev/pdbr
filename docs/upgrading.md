# Upgrading

## 0.x → 1.0

### Catalog format 10 (pdbcore)

- **Regenerate schema caches.** The catalog format is now 10, and `serve`
  and `schema check` refuse caches written by earlier releases (format 9).
  The error names the program that wrote the cache when the cache records
  it. Run `pdbr schema dump` again. New caches record the writer (`pdbr`,
  its version and the pdbcore version).
- **Identity `BY DEFAULT` columns are writable.** A
  `GENERATED BY DEFAULT AS IDENTITY` column is no longer
  `400 column_readonly`:
  - On `POST` it is optional, like a serial column: an omitted value takes
    the sequence's next one.
  - `PATCH` and `PUT` bodies may set it.
  - A key on it serves as the default `PUT` conflict target, and its
    single-row path now offers `PUT`.
  - OpenAPI lists it in the `.insert`, `.update` and `.upsert` schemas
    without `readOnly`.

  Identity `ALWAYS` and generated columns are unchanged.
- **PostgreSQL minor upgrades are not drift.** The cache hash covers the
  server's major version only, so `pdbr schema check` and the watch poll no
  longer report a PostgreSQL minor upgrade. A major upgrade still counts.
- **Stable overload order.** Functions are ordered by schema, name and
  input parameter types (fewer parameters first). The overload that keeps
  an RPC route is now always the one with the fewest input parameters.
  Before, it could change from one run to the next.
- **PostgreSQL 14 is the minimum.** Older servers are refused at
  introspection and on every pool connection, so this also applies when
  booting from a schema cache.
