# Upgrading

## 0.x → 1.0

### Catalog format 10 (pdbcore)

- **Regenerate schema caches.** The catalog format is now 10, and `serve`
  and `schema check` refuse caches written by earlier releases (format 9).
  The error names the program that wrote the cache when the cache records
  it. Run `pdbr schema dump` again. New caches record the writer (`pdbr`,
  its version and the pdbcore version).
- **Identity `BY DEFAULT` columns are writable.** A
  `GENERATED BY DEFAULT AS IDENTITY` column is no longer
  `400 column_readonly`:
  - On `POST` it is optional, like a serial column: an omitted value takes
    the sequence's next one.
  - `PATCH` and `PUT` bodies may set it.
  - A key on it serves as the default `PUT` conflict target, and its
    single-row path now offers `PUT`.
  - OpenAPI lists it in the `.insert`, `.update` and `.upsert` schemas
    without `readOnly`.

  Identity `ALWAYS` and generated columns are unchanged.
- **PostgreSQL minor upgrades are not drift.** The cache hash covers the
  server's major version only, so `pdbr schema check` and the watch poll no
  longer report a PostgreSQL minor upgrade. A major upgrade still counts.
- **Stable overload order.** Functions are ordered by schema, name and
  input parameter types (fewer parameters first). The overload that keeps
  an RPC route is now always the one with the fewest input parameters.
  Before, it could change from one run to the next.
- **PostgreSQL 14 is the minimum.** Older servers are refused at
  introspection and on every pool connection, so this also applies when
  booting from a schema cache.

### Authentication, roles, claims and strict configuration

pdbr 1.0 adopts pdbcore's identity configuration and strict loading. Every
item below is breaking.

- **The `rls` section is gone.** It is split into `auth` (how a request
  proves who it is), `roles` (which database role it runs as) and `claims`
  (where its claims are exposed to SQL); see the table below and
  [rls.md](rls.md). Loading an old config fails and names the new key
  (`unknown key rls.enabled: moved to roles.switch`).
- **Anonymous access is opt-in.** `roles.anonymous` (formerly
  `rls.anonymous_role`, default `anonymous`) is empty by default: requests
  without credentials are answered `401` with the new code `auth_required`
  and `WWW-Authenticate: Bearer`. Set `roles.anonymous: anonymous` to keep
  serving them. Every authentication `401` now carries a
  `WWW-Authenticate` challenge, and `403 role_not_allowed` carries
  `Bearer error="insufficient_scope"`. The OpenAPI document marks
  `bearerAuth` as required in jwt mode without `roles.anonymous`.
- **Claims live under `jwt.claims` by default.** `claims.prefix` (formerly
  `rls.claims_prefix`) defaults to `jwt.claims` instead of `pdbq.claims`.
  Update policies to read `current_setting('jwt.claims.<claim>', true)`, or
  set `claims.prefix: pdbq.claims` to keep the old ones. The new
  `claims.json_setting` (e.g. `request.jwt.claims`) also exposes every claim
  as one JSON object.
- **`roles.switch: false` replaces `rls.enabled: false`** and no longer
  turns authentication off: credentials are still verified and claims still
  set, only the role switch is skipped. For no authentication at all also
  set `auth.mode: none`. The `--rls.enabled` flag is now `--roles.switch`;
  new flags `--auth.mode` and `--roles.anonymous`.
- **Fail closed.** pdbr refuses to start in `jwt` mode without a secret,
  secret file or JWKS URL, in `headers` mode without
  `auth.headers.trusted_proxies` (an empty list used to trust every peer),
  and in `none` mode with `roles.switch` on but no `roles.anonymous`. A
  JWT role claim that is not a non-empty string is `401 invalid_token`
  (it used to fall back to the default role); a request that resolves to no
  role is `403 role_not_allowed`.
- **The default configuration needs a key.** It verifies JWTs, so `pdbr
  serve` and `pdbr config validate` on defaults fail until one of
  `auth.jwt.secret`, `auth.jwt.secret_file` or `auth.jwt.jwks_url` is set
  (or `auth.mode: none`). `pdbr config init` writes a starter with
  `auth: {mode: none}` and `roles: {switch: false}` that runs with only
  `database.url`.
- **CLI identity.** `pdbr request`, `pdbr schema dump`, `pdbr schema check`
  and `pdbr plugins list` run as the connection role without credentials
  (`auth.mode: none` and `roles.switch: false` are forced before
  validation), so they work on a default config. `pdbr request` used to run
  as the anonymous role when RLS was on. `pdbr plugins list` reports an
  invalid configuration instead of silently listing the defaults.
- **Strict configuration.** Unknown keys in the YAML file are errors, and
  so are `PDBR_*` environment variables inside a config section that name no
  key (`PDBR_RLS_ENABLED`, a typo such as `PDBR_SERVER_ADR`); messages name
  the replacement or the closest key. Other `PDBR_*` variables
  (`PDBR_TEST_DATABASE_URL`) are ignored.
- **`log.format` is validated**: only `text` and `json` are accepted.
- **Plugin names are snake_case**, with no aliases: `smart_comments`,
  `advanced_filters`, `nested_mutations` (`postgis` is unchanged).
  `plugins.disabled` only accepts built-in names (a kebab-case name gets a
  did-you-mean hint), and `plugins.settings.advanced-filters` /
  `nested-mutations` moved to `plugins.settings.advanced_filters` /
  `nested_mutations`.
- **Typed plugin settings.** `plugins.settings` is a typed section per
  built-in plugin, not a free-form map: unknown or mistyped settings are
  errors, environment values work
  (`PDBR_PLUGINS_SETTINGS_ADVANCED__FILTERS_RELATIONS=false`; they were
  ignored before), and `nested_mutations.max_depth` / `max_operations` must
  be `>= 1` (a non-positive value used to be ignored). Third-party plugins
  cannot be configured through `plugins.settings` or disabled through
  `plugins.disabled`; configure them where they are constructed. In Go,
  the plugin constructors take their `Settings` struct
  (`advancedfilters.New(advancedfilters.DefaultSettings())`), and
  `smartcomments.New()` takes none.
- **`database.statement_timeout` defaults to `25s`** (was `30s`), below
  `server.request_timeout` (`30s`), so a slow statement fails with
  `504 pg:57014` before the request itself times out.
- **SQLSTATE class 21 is a client error.** `21000` (a bulk upsert naming one
  conflict key twice, a scalar subquery returning several rows) is
  `400 pg:21000` with PostgreSQL's message in `prod`, instead of a
  sanitized `500`.
- **CORS** responses add `Vary: Origin` without dropping
  `Vary: Accept-Encoding`, and list the headers pdbr sets in
  `Access-Control-Expose-Headers` (`Content-Range`, `ETag`, `Link`,
  `Location`, `Preference-Applied`, `X-Total-Count`, …).
- **Embedding API** (`pdbr` package): `RLSConfig` is gone; use
  `AuthConfig`, `JWTConfig`, `HeadersConfig`, `RolesConfig`,
  `ClaimsConfig`. `PluginsConfig` is `confx.Plugins[PluginSettings]`.
  An invalid auth configuration is returned as an error by `App.Serve` /
  `App.Handler` instead of falling back.

### Configuration regrouped

pdbr 1.0 moves the request limits, the transaction policy and the OpenAPI
switches out of `server`, using the same section and key names as pdbq for
the concepts both products share (`limits.*`, `transactions.partial.*`,
`schema.domains`, `aggregates.enabled`). Every item below is breaking.
Loading a config or environment that uses an old key fails and names the
new one (`unknown key server.tx_end: moved to transactions.end`,
`unknown environment variable PDBR_SERVER_MAX__COST (server.max_cost):
moved to PDBR_LIMITS_MAX__COST`); flags are renamed the same way
(`--server.tx_end` is `--transactions.end`).

- **`server.base_path` defaults to `""`** (was `/api`): the API is mounted
  at the root, as in PostgREST, so `GET /api/users` is now `GET /users` and
  the OpenAPI document is at `/openapi.json`. Set `server.base_path: /api`
  to keep the old routes. Contract paths default to `<base_path>/<name>`,
  so they move to `/<name>` too unless they set `path`. `pdbr config init`
  no longer writes `base_path`.
- **`limits` section.** `server.max_body_bytes`, `max_cost`,
  `max_page_size` and `max_headline_document` moved to `limits.*`, and
  `server.max_embed_depth` is `limits.max_depth`. `limits.max_body_bytes`
  and `limits.max_cost` must now be `>= 1`.
- **`transactions` section.** `server.tx_end` is `transactions.end`;
  `server.partial_bulk_writes` / `partial_bulk_max_items` are
  `transactions.partial.enabled` / `max_items`, the shape pdbq uses for its
  partial mutations.
- **Every write runs in a transaction.** `transactions.mutations` is
  removed, and so is `plugins.settings.nested_mutations.force_transactions`
  (it only mattered with `transactions.mutations: false`). Turning
  transactions off for writes saved one round trip at most, and conflicted
  with `transactions.end: rollback`, `Prefer: tx=`, `Prefer: max-affected`
  and partial success, which all need one. Both keys are now unknown keys
  (`unknown key transactions.mutations`); delete them.
- **`openapi` section.** `server.openapi` is `openapi.enabled` (still on by
  default; pdbq's schema document, introspection plus SDL, is on by default
  too). New: `openapi.title` (`info.title`, default `pdbr`) and
  `openapi.server_url`, an absolute origin put before the base path in
  `servers[0].url` (default empty: the relative base path, as before).
- **`schema.domains`** replaces `server.openapi_domains` (same name as in
  pdbq, where it was `schema.domain_scalars`).
- **`mutations.allow_unfiltered`** replaces
  `server.allow_unfiltered_mutations`.
- **`aggregates.enabled`** replaces `server.aggregates` (pdbq uses the same
  key). The `400 aggregates_disabled` detail and the postgis plugin's
  `aggregates` setting now name `aggregates.enabled`.
- **Embedding API.** `config.Server` lost the moved fields (see
  `Config.Limits`, `Config.OpenAPI`, `Config.Mutations`,
  `Config.Aggregates`, `Config.TX`); `Config.TX` is pdbr's own
  `config.TX` (no `Mutations`). `exec.Options.TxMutations` and
  `nestedmutations.Settings.ForceTransactions` are gone.

### Error codes

pdbr 1.0 closes the problem `code` vocabulary
([errors.md](errors.md#code-vocabulary)): every code is listed there, and
each grammar code names the part of the request at fault. Clients that
branch on `code` need these changes; statuses are unchanged.

- **`invalid_filter` is split.** It now means a filter only. Reserved query
  parameters and path keys answer `invalid_parameter`, and function and
  computed-column argument values answer `invalid_argument`.
- **An RPC argument value is `invalid_argument` in a `POST` body too**
  (it was `invalid_body`). A body that is not a JSON object stays
  `invalid_body`.
- **A hint that selects no relation is `unknown_relation`** (it was
  `ambiguous_relation`). `ambiguous_relation` is only for a key with
  several FKs and no hint.
- **`embed_depth_exceeded` is `depth_exceeded`**, the code pdbq uses for
  the same `limits.max_depth` limit (also for the nested-mutation depth).
- **`not_implemented` (501) is gone.** It was never emitted.
- **A hook's `UserError` without a code is `invalid_parameter`** (it was
  `invalid_filter`).
- **Embedding API**: `compile.ErrNotImplemented` and the
  `not_implemented` code constants are removed.

| 0.x | 1.0 | Examples |
|---|---|---|
| `400 invalid_filter` | `400 invalid_parameter` | `limit=abc`, `offset=-1`, `count=yes`, `order=id.sideways`, `distinct=` errors, a duplicate parameter, `on_conflict=` without `resolution=`, `limit` on a write or a single-row path, `posts.after=`, a missing, malformed or unused `near=` / `trgm=` / `vec=` / `latlon=` / `levenshtein=`, `geometry=` without `Accept: application/geo+json`, `/users/abc`, related ordering while it is disabled |
| `400 invalid_filter` | `400 invalid_argument` | `GET /rpc/f?n=abc`, `select=excerpt(max_chars=x)`, a row argument that is not JSON |
| `400 invalid_body` | `400 invalid_argument` | `POST /rpc/f {"n": "abc"}`, a row argument with an unknown key |
| `400 ambiguous_relation` | `400 unknown_relation` | `select=comments!nope(id)`, `posts!left(*)`, `users?posts!bad.title=eq.x` |
| `400 embed_depth_exceeded` | `400 depth_exceeded` | `select=` nested deeper than `limits.max_depth`, nested mutations deeper than `nested_mutations.max_depth` |
| `501 not_implemented` | — | removed |
| `400 invalid_filter` (hook `UserError` with an empty `Code`) | `400 invalid_parameter` | |

These keep `invalid_filter`: an unknown operator or one the column's type
does not take, a malformed operand or list, a value that does not coerce
(`id=eq.abc`), relation-filter grammar, filters on a write that takes none,
and a rank order term or headline without its full-text filter.

### Operator, parameter and pseudo-column names

pdbr 1.0 renames parts of the query grammar so the names follow one rule
each and a DDL change can never change what a request means. Every item
below is breaking; the old spellings are `400` errors (`invalid_filter`,
`invalid_parameter` or `unknown_column`), not aliases.

- **The `~` namespace.** The reference parameters and every pseudo-column
  start with `~` ([api.md](api.md#the--namespace)). Before, `near=`,
  `trgm=`, `vec=`, `latlon=`, `levenshtein=` and `geometry=` turned into
  filters (or RPC arguments) as soon as a column or argument of that name
  existed, and a real column named like a pseudo-column (`location_area`)
  silently replaced it. Now `~near=` is always the parameter, `near=eq.x`
  is always a filter on a column named `near`, and `select=~location_area`
  is always the accessor. Pseudo-columns answer under their `~` key
  (`{"~location_area": 12.5}`) unless aliased. A column whose name starts
  with `~` can no longer be named in `select=`, filters or `order=` (only
  `select=*` returns it); pdbr logs a warning for it.
- **Spatial operators are snake_case.** `st_containsproperly`,
  `st_coveredby`, `st_exactlyequals`, `st_intersects3d`,
  `bbox_containedby`, `bbox_leftof`, `bbox_rightof`,
  `bbox_overlapsor{leftof,rightof,below,above}` and `bbox_intersectsnd` are
  spelled as in the table below.
- **Redundant spatial operators are gone.** `bbox_intersects2d` is
  `bbox_intersects` with a geometry operand (an operand starting with `(` is
  still an envelope), and `st_orderingequals` is `st_exactly_equals`, which
  matches the same rows and can use a B-tree index.
- **Raster `intersects` is `st_intersects`**, like the geometry operator.
  OpenAPI lists `x-pdbr-filter-ops: [st_intersects, is]`.
- **One distance vocabulary, `<metric>_distance`.** Order terms, score
  pseudo-columns and thresholds share the metric name: `.dist` is
  `.st_distance` (score `~<col>_st_distance`), the pgvector and cube terms
  drop `vec_` (`vec_cos` is `cosine_distance`, `vec_ip` is
  `negative_inner_product`), the trigram terms spell out `distance`
  (`trgm_dist` is `trgm_distance`), and the earthdistance and Levenshtein
  terms and thresholds gain `_distance`. The trigram similarity scores are
  `~<col>_trgm_similarity` and the word forms, and the miles score is
  `~<col>_earth_miles_distance`.
- **Errors.** A filter or `order=` term on a pseudo-column that takes none
  is `400 column_not_filterable` / `column_not_orderable` (it was
  `unknown_column`). `~geometry=` on a resource without a spatial column
  is the `406` of `Accept: application/geo+json` (it was a filter).
- **Embedding API.** `Resource.NameTaken` is gone, `Resource.Pseudo` is
  keyed by the `~` names, and a score's `Score.Param` holds `~near`,
  `~vec`, … .

|---|---|
| `near=`, `trgm=`, `vec=`, `latlon=`, `levenshtein=`, `geometry=` | `~near=`, `~trgm=`, `~vec=`, `~latlon=`, `~levenshtein=`, `~geometry=` |
| `<col>_area`, `<col>_srid`, `<col>_x`, … (PostGIS accessors) | `~<col>_area`, `~<col>_srid`, `~<col>_x`, … |
| `<col>_width`, `<col>_value`, `<col>_summary_stats`, … (raster) | `~<col>_width`, `~<col>_value`, `~<col>_summary_stats`, … |
| `<col>_headline`, `<col>_nlevel`, `<col>_parent`, `<col>_lca`, `<col>_subpath`, `<col>_icount` | the same with `~` |
| `order=<col>.dist`, `<col>_distance` | `order=<col>.st_distance`, `~<col>_st_distance` |
